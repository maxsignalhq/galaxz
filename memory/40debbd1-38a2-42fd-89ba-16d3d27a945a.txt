--------------------------------------------------------------------------------
PROJECT OVERVIEW
--------------------------------------------------------------------------------
Galaxz is a multi-agent AI QA pipeline. The first agent is "Vega", which runs
three sequential stages:
  1. Analyzer     — extracts structured requirements from raw text
  2. Test Designer — generates test cases from requirements
  3. Bug Reporter  — generates bug reports from failing test results

All stage activity is published to a Redis stream ("galaxz:tasks") via a thin
client called AetherClient. This stream is the shared event bus between agents
(future agents like Rigel/Andromeda will consume from it).

KEY DESIGN DECISIONS
--------------------------------------------------------------------------------

1. PYTHONPATH
   - Set ENV PYTHONPATH=/app in Dockerfile so `galaxz.*` imports resolve without
     a setup.py or pyproject.toml.

2. TASK CONTRACT (core/contracts/task.py)
   - Pydantic v2 BaseModel. Immutable — never mutated in place.
   - transition_status() returns a new contract via model_copy(update={...}).
   - VALID_TRANSITIONS enforces a strict state machine:
       pending → running → complete/retrying/failed
       retrying → running/failed
       complete and failed are terminal.
   - started_at is set automatically on → running.
   - completed_at is set automatically on → complete or → failed.

3. AETHER CLIENT (core/aether/client.py)
   - Wraps redis-py. Single stream key: "galaxz:tasks".
   - Publishes via XADD with field name "data" (JSON-serialised contract).
   - Publish-only for now; consumer/read methods are a future concern.
   - get_aether_client() reads REDIS_URL from env (default: redis://localhost:6379).

4. LLM PROVIDER (core/llm/provider.py)
   - load_provider_config() reads config/providers.yaml and resolves ${ENV_VAR}
     references using re.sub against os.environ. Unresolved vars are left as-is.
   - call_llm() uses litellm.completion() with model string formatted as
     "{provider}/{model}" (litellm routing convention).
   - Wraps all litellm exceptions in RuntimeError("LLM call failed: {original}").

5. STAGE FUNCTIONS
   - All three stages follow the same pattern:
       a. Build system prompt + user message with schema hint
       b. Call call_llm()
       c. Parse response with Model.model_validate_json()
       d. Recompute all counts/summaries locally (never trust LLM-provided counts)
       e. Return via model_copy(update={...})
   - Analyzer: includes AnalyzerOutput.model_json_schema() in the user message.
   - Test Designer: initialises coverage_summary from input req_ids so silently
     skipped requirements still appear with count=0 in uncovered_reqs.
   - Bug Reporter: returns early (no LLM call) if there are no fail/blocked results.
     pass_rate is always computed locally, never from LLM output.

6. PIPELINE (agents/vega/pipeline.py)
   - Generates one run_id (uuid4) shared across all three stage contracts.
   - Each stage follows: create contract → publish(pending) → transition(running)
     → publish → run stage → transition(complete) + set output → publish.
   - On exception: transition(failed) + set error → publish → re-raise.
   - Stage 3 is skipped entirely (no contract created) when test_results is None.
   - AetherClient is closed in a finally block regardless of outcome.

7. CLI (cli/run.py)
   - Click group "galaxz" with one command "vega".
   - --input (required): path to requirements text file.
   - --results (optional): path to JSON file containing list of TestResult dicts.
   - --config (default: config/providers.yaml): provider config path.
   - --output (optional): path to write full pipeline result as JSON.
   - Prints run_id, requirement count, test case count, bug count (or "Stage 3 skipped").
   - All exceptions caught → print "Error: {message}" → sys.exit(1).
   - Parameter renamed input_path internally to avoid shadowing Python built-in.
   - json.dump uses default=str to handle datetime fields in output.

8. DOCKER
   - Two services: aether (Redis 7 alpine) and galaxz (built from Dockerfile).
   - docker-compose.yml uses env_file: .env so secrets stay out of the image.
   - config/ is bind-mounted to /app/config so providers.yaml can be edited
     without rebuilding the image.
   - docker-compose.yml has image: galaxz:latest on the galaxz service (added
     post-creation by user/linter).

9. FUTURE PLACEHOLDERS (noted in code but not yet implemented)
   - BugReport.rigel_handoff: bool — Phase 2, Andromeda routes flagged bugs to Rigel.
   - TaskContract.retry_count / max_retries — retry logic not yet wired in pipeline.
   - TaskContract.prompt_tokens / output_tokens — stage functions do not currently
     surface token counts back to the pipeline (call_llm returns them but stage
     functions discard them). Future: thread tokens through stage return values.

HOW TO RUN LOCALLY
--------------------------------------------------------------------------------
1. Copy .env.example to .env and fill in ANTHROPIC_API_KEY.
2. docker-compose up --build
3. In a separate shell:
   docker-compose exec galaxz python -m galaxz.cli.run vega \
     --input /path/to/requirements.txt \
     [--results /path/to/test_results.json] \
     [--output /path/to/output.json]
